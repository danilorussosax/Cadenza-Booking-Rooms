# AGENTS.md — Cadenza

## Project structure

Monorepo with three workspaces:

```
backend/     Express 5 + Sequelize 6 API (serves on :3000, also serves built frontend in prod)
frontend/    React 19 + TypeScript 6 SPA (Vite 8, dev on :5173, proxies /api → :3000)
e2e/         Playwright end-to-end tests
```

The root `package.json` is a meta-package for shared devtools only (husky, lint-staged, commitlint, prettier).

In production, the backend serves `/api/*` endpoints AND the frontend `dist/` bundle behind nginx. There is no separate static file server.

## Commands (always run from monorepo root unless noted)

```bash
npm run dev               # backend (nodemon :3000) + frontend (vite :5173) in parallel
npm run dev:backend       # backend only
npm run dev:frontend      # frontend only
npm run build             # frontend build → frontend/dist/ (typecheck + vite bundle)
npm run start             # production: node backend/server.js (serves API + dist)

npm run test              # vitest backend → vitest frontend (sequential)
npm --prefix backend test                 # backend only
npm --prefix backend test -- tests/integration/auth.test.js   # single file
npm --prefix frontend test                # frontend only
npm run e2e               # Playwright (runs from frontend/)
npm run lint              # eslint backend → eslint frontend
npm run format            # prettier over entire monorepo
npm run format:check      # prettier --check (CI gate)

cd backend && npm run seed               # re-seed admin + default rules
DB_SYNC_MODE=alter cd backend && npm start   # apply model schema changes (development)
```

## Commit convention

Uses `@commitlint/config-conventional` with two extra types:

```
security   → security fixes, vulnerability patches, hardening
gdpr       → privacy-related changes (consent, retention, data export)
```

Format: `type(scope): description` (header max 100 chars). See `commitlint.config.cjs`.

The pre-commit hook runs `lint-staged` (prettier + eslint fix on staged) and `gitleaks` (secrets scan) if gitleaks is installed locally.

## Backend

### Entry point & config

`backend/server.js` loads dotenv from `backend/.env` explicitly (not via cwd). Then:

1. `lib/config.js` validates env vars
2. `lib/secrets.js` asserts production JWT_SECRET
3. `lib/sentry.js` init (no-op without SENTRY_DSN)
4. Sequelize sync (controlled by `DB_SYNC_MODE` env)

**`DB_SYNC_MODE`** controls schema sync at startup:

- `safe` (default): create missing tables/indices, never alter existing
- `alter`: sync({alter:true}) — adjusts schema to match models. Use once after model changes, then switch back to `safe`
- `force`: DROP + CREATE all tables (destroys data)
- `none`: skip sync entirely

### Database

- **Production**: PostgreSQL 16 with `EXCLUDE` constraint (`bookings_no_overlap`) as anti-overlap safety net at DB level
- **Development default**: SQLite (zero-config, file `data/database.sqlite`)
- Sequelize `paranoid: true` (soft-delete) on 10 models: do `findAll({ paranoid: false })` to include deleted rows
- **PgBouncer** is required in PM2 cluster mode (3 instances × Sequelize pool = 60 connections, Postgres max_connections = 50). `ecosystem.config.js` forces `DB_PORT=6432` and `DB_PGBOUNCER=true` via PM2 env

### Test quirks

- Backend tests use **SQLite in-memory** by default (no Postgres needed). File parallelism is **disabled** (`fileParallelism: false`, `singleFork: true`) because integration tests share the DB.
- The EXCLUDE constraint test (`tests/integration/excludeConstraint.test.js`) requires a dedicated Postgres database. Set `DB_DIALECT=postgres DB_NAME=cadenza_test` to run it.
- Analytics tests are Postgres-only (SQL queries use `EXTRACT`/`date_trunc`). Covered by the CI "Backend · Postgres-only tests" job.
- Global test helpers from `tests/setup.js`: `resetDatabase()` is available in test scope.
- Coverage thresholds: statements ≥72 / lines ≥73 / functions ≥78 / branches ≥60. CI blocks on regressions.

## Frontend

### Import alias

`@` → `frontend/src/` (configured in `vite.config.ts` and `tsconfig`).

### Build details

- **Manual chunking** in `vite.config.ts`: React + react-router MUST stay in the same chunk (`vendor-react`). Separating them causes `Cannot read property 'createContext' of undefined`.
- Sentry sourcemap upload is conditional: only if `SENTRY_AUTH_TOKEN`, `SENTRY_ORG`, and `SENTRY_PROJECT` are all set.
- Chunk size warning raised to 600 KB (recharts + d3 exceed the Vite default 500 KB).

### Dev notes

- PWA Service Worker is disabled in `vite dev` (`devOptions: { enabled: false }`).
- The `/api` proxy in Vite forwards to `http://localhost:3000` — the backend must be running.
- PWA manifest is served statically from `frontend/public/manifest.webmanifest` (not generated by the Vite plugin).

## Code style

- **Prettier**: single quotes, trailing commas, 100 char width, 2-space indent. Markdown gets `proseWrap: preserve`. YAML gets double quotes only.
- **EditorConfig**: LF line endings, UTF-8, 2-space indent everywhere.
- **ESLint**: flat configs (ESLint 9+). Backend uses CommonJS with `eslint-plugin-n` + `eslint-plugin-security`. Frontend uses `typescript-eslint strictTypeChecked` with many rules downgraded to `warn` (see the eslint config files for the full rationale).
- **Unused variables**: prefix with `_` to suppress lint errors (both workspaces).

## Testing strategy

| Layer                    | Runner                    | Scope                                                                |
| ------------------------ | ------------------------- | -------------------------------------------------------------------- |
| Backend unit/integration | Vitest (SQLite in-memory) | `backend/tests/**/*.test.js`                                         |
| Backend Postgres-only    | Vitest with real Postgres | CI job only; `excludeConstraint`, `analyticsAggregations`            |
| Frontend component/unit  | Vitest + jsdom            | `frontend/tests/**/*.test.{ts,tsx}` — `src/components/` + `src/lib/` |
| E2E                      | Playwright                | `frontend/tests/e2e/` or `e2e/` workspace                            |
| Soak                     | k6                        | `loadtest/soak.sh` — run on staging before major rollout             |

Frontend component coverage scope excludes page-level components and admin dialog forms (covered by E2E instead — see `frontend/vitest.config.ts` for the full exclusion list).

## CI (GitHub Actions)

4 parallel jobs in `.github/workflows/ci.yml`:

1. **gitleaks** — full history secrets scan
2. **Backend · lint + test + coverage** — matrix: TZ=Europe/Rome and TZ=UTC (timezone-sensitive tests)
3. **Backend · Postgres-only tests** — EXCLUDE constraint + analytics queries
4. **Frontend · lint + test + coverage + typecheck + build** — also runs `format:check`

CI runs on push to `main`/`develop` and on all PRs. Concurrency group cancels redundant runs.

## Deploy

`./deploy.sh` deploys to the production VPS. Key behaviors:

- Deploys from `git archive HEAD` (snapshot of committed code), **never** from the working tree
- Supports `--ref=<commit>` to deploy a specific commit
- `--no-build` skips frontend build but refuses if source files are newer than dist
- `--update-deps` runs `npm outdated` per workspace and asks to `npm update` before deploy
- Compares lockfile versions with the server — **aborts if the server has newer modules** (prevents regression)
- Healthchecks `/api/ready` (5 retries × 3s) after PM2 restart, verifying DB connectivity
- Requires SSH alias `cadenza-vps` in `~/.ssh/config`

## i18n

5 languages: Italian (default), English, Spanish, German, French. Uses `i18next` + `react-i18next`. Locale files: `frontend/src/i18n/locales/{it,en,es,de,fr}.json`. Backend errors use stable `error.code` keys (e.g. `BOOKING_CONFLICT`, `EMAIL_ALREADY_REGISTERED`).

## Key gotchas

- **Node.js version**: root requires ≥20, backend requires ≥18. Use Node 20 LTS for development.
- **`process.cwd()`**: backend dotenv uses `__dirname`, not cwd — safe to invoke `node backend/server.js` from any directory.
- **React + react-router chunking**: if you change the manual chunk strategy in `vite.config.ts`, keep react+react-dom+react-router in the same chunk (rule 1 in the config comments).
- **Analytics routes Postgres-only**: `backend/routes/analytics.js` is excluded from coverage because it uses Postgres-specific SQL. Covered by the separate CI job.
- **`@emnapi/runtime` extraneous**: warnings about extraneous packages in `npm ls` are expected (these are optional native deps pulled by sharp, safe to ignore).
